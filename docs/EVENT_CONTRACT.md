# Формат событий v1

Предложение по задаче #12 для ревью команды. Это формат обмена, не схема таблиц. Библиотека AgentObservatory.Contracts содержит DTO для будущих API и SDK; endpoint приёма пока не реализован.

## Пакет

Поля JSON записываются в camelCase. В C# используем System.Text.Json с JsonSerializerDefaults.Web.

| Поле | Смысл |
|---|---|
| schemaVersion | Целое число 1; обязательное поле |
| projectId | UUID проекта; должен совпадать с правами ключа отправителя |
| events | Непустой массив событий; в одном пакете могут быть разные запуски одного проекта |

Размер пакета и HTTP-адрес определим в задаче #8. Версия задаётся явно. Будущий Collector отклоняет неподдерживаемую версию, неизвестные типы и некорректный пакет до записи. Дополнительные неизвестные поля JSON игнорируются для совместимости; существующие поля не меняют смысл внутри v1.

## Событие

| Поле | Смысл |
|---|---|
| eventId | UUID конкретного события; сохраняется при повторной отправке |
| runId | UUID запуска |
| operationId | UUID операции: запуска, агента, model call или tool call |
| parentId | UUID родительской операции, не родительского события |
| agentId | UUID агента; для событий самого Run отсутствует |
| timestamp | Время события у источника в UTC: ISO 8601 с Z или +00:00 |
| type | Строковый тип из таблицы ниже |
| status | running, succeeded, failed или cancelled |
| durationMs | Длительность в миллисекундах для finished-события; неотрицательная, может быть дробной |
| name | Необязательное название операции |
| usage | Необязательная статистика завершённого вызова модели |
| metadata | Необязательный JSON-объект с дополнительными данными |

Обязательны eventId, runId, operationId, timestamp, type и status. Идентификаторы не могут быть пустыми UUID. Отсутствующий необязательный параметр и null эквивалентны. ReceivedAt задаёт сервер, отправитель его не передаёт. Часы разных машин не используются для вычисления durationMs: длительность измеряет источник.

## Типы и статусы

| Типы | Статус | Дополнительные правила |
|---|---|---|
| runStarted | running | operationId = runId; parentId и agentId отсутствуют |
| runFinished | succeeded / failed / cancelled | Та же операция; parentId и agentId отсутствуют |
| agentStarted | running | agentId обязателен; parentId — Run или родительский Agent |
| agentFinished | succeeded / failed / cancelled | Те же agentId, operationId и parentId, что у начала |
| modelCallStarted, toolCallStarted | running | agentId обязателен; parentId — Agent или содержащая вызов операция |
| modelCallFinished, toolCallFinished | succeeded / failed / cancelled | Та же операция, агент и родитель, что у начала |
| error | failed | Ссылка на operationId операции с ошибкой; не заменяет её finished-событие |
| retry | running | Ссылка на неудачную operationId; metadata.attempt — номер следующей попытки, начиная с 2 |

Каждое started/finished — отдельное событие с собственным eventId, но общим operationId. Для каждой новой попытки вызова создаётся новая операция. retry относится к предыдущей неудачной операции; metadata.nextOperationId связывает её со следующей попыткой. Количество повторов считаем по retry-событиям, без двойного подсчёта failed-вызовов.

Для error в metadata используем code и, опционально, message. stackTrace и содержимое запросов по умолчанию не отправляем. Для tool call имя инструмента хранится в name. usage содержит model и необязательные неотрицательные inputTokens/outputTokens; неизвестное количество остаётся null, а не превращается в ноль. usage применяется только к modelCallFinished, durationMs — только к finished-событиям. Числовые значения type/status не допускаются.

Эти семантические правила должен проверять Collector в задаче #8. DTO сейчас задают типы и обязательность присутствия полей при десериализации, но не проверяют Guid.Empty, сочетания типа/статуса, неотрицательные значения, UTC и версию схемы. Эти проверки ещё предстоит реализовать.

## Порядок и повторы

- События могут прийти не по порядку, в разных пакетах или после runFinished. Поздние события не переоткрывают завершённый запуск.
- Отсутствующий started или родитель не делает пакет некорректным: он мог задержаться или потеряться. Храним событие, показываем незавершённую связь. Проверку согласованности пар делаем после появления обоих событий.
- Для показа сортируем по timestamp и затем по канонической строке eventId. Это порядок отображения, а не гарантия причинности между разными источниками.
- Уникальность события: projectId + eventId. При retry доставки сохраняются исходные ID и содержимое; существующий eventId не перезаписывается.
- Один operationId используется только внутри одного Run. Новое завершение той же операции с другим исходом — конфликт, а не изменение старого события; обработку таких конфликтов определяем в Collector.
