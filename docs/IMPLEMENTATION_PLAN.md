# План реализации проекта

Это целевой план, а не отчёт о готовом коде. Обозначения AO ниже — локальные идентификаторы задач, не номера GitHub Issues.

## Правила

В команде три участника со смешанным распределением задач. Автора или соавторов и ревьюера выбираем для каждой задачи. Исполнители реализуют код, тесты и документацию своей части; постоянного закрепления направлений за людьми нет.

Зависимости задают порядок. Не начинаем SDK и граф до согласования контракта. Интеграционные тесты появляются вместе со сценарием, а не в конце проекта.

## Первые две итерации

**Итерация 1:** командой согласовать AO-01; распределить AO-02, fixtures/API examples и подготовку тестового сценария между участниками. После основы — AO-03 и затем AO-04. Итог: HTTP → PostgreSQL → GET, подтверждённый интеграционным тестом.

**Итерация 2:** распределить AO-05, AO-06 и подготовку AO-07 с учётом зависимостей и договорённостей команды. Совместно проверить дубли и отказ Collector. Сроки определяем после первой итерации по реальному темпу.

## Демонстрация на собеседовании

1. Запустить Compose и sample.
2. Показать Run с двумя параллельными агентами, model/tool calls, ошибкой и retry.
3. Повторно отправить batch и показать отсутствие дублей.
4. Остановить Collector: sample продолжает работать; показать результат восстановления и ограничения очереди.
5. Открыть завершённый Run после перезапуска backend.
6. Показать интеграционный тест, индекс и explain, CI и один PR с review.

В README релиза фиксируем измеренные результаты и условия теста. Не заявляем гарантированную доставку, highload или overhead без измерений.
