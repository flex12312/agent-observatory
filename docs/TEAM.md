# Команда и работа над задачами

В команде два backend-разработчика: @IKSXXX и @flex12312. Оба работают с ASP.NET Core, PostgreSQL, SDK и тестами. Отдельного frontend-разработчика и обязательного третьего участника нет.

## Разделение по функциональности

На каждый этап выбираются автор и ревьюер. Распределение ниже — стартовое предложение; конкретного исполнителя фиксируем в Issue перед началом работы.

| Направление | Результат |
|---|---|
| Projects / Runs / Access | API проектов и запусков, EF Core migrations, запросы и индексы, доступ к проектам |
| Telemetry / SDK / Live | Приём событий, идемпотентность, SDK, background exporter, SignalR |

Один участник начинает с Projects / Runs, другой — с Telemetry / SDK. На следующем этапе меняемся задачами: каждый должен реализовать API, работу с БД, асинхронный сценарий и интеграционные тесты.

Контракт событий, ограничения доставки и изменения общей схемы БД обсуждаем вместе до реализации. В одном этапе миграции координирует один автор.

## Общая работа

- Каждый пишет тесты своей функциональности и обновляет документацию.
- Каждый PR проверяет второй участник.
- Docker, CI, демонстрационный сценарий и небольшой UI — общие задачи.
- UI показывает backend: список запусков, события, граф, timeline и детали.
- Каждый может объяснить полный путь события от SDK до БД и интерфейса.

## Готовность задачи

Работа готова после реализации критериев, проверки тестами, review и merge. Закрытие Issue как duplicate не означает выполнение функциональности.

Актуальная последовательность задач и критерии: [план реализации](IMPLEMENTATION_PLAN.md). Старые назначения и ссылки в Issues требуют сверки с этим планом.
